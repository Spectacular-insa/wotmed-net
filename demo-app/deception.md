# Deception Mechanisms

## Overview

The Demo Application will include controlled deception mechanisms to
help identify suspicious interactions within the Wotmed-Net testing
environment.

The deception layer will be added to the existing Student Management
System without affecting its normal application functionality.

## Decoy Resources

Decoy resources are application resources that appear legitimate but
are created specifically for security testing and detection.

Planned decoy resources include:

- Decoy administrative resources
- Hidden application resources
- Decoy configuration values
- Other controlled resources used for testing

These resources will not contain real credentials or production data.

## Deception Triggers

A deception trigger occurs when a user or security test interacts with
a resource that is not normally accessed during legitimate application
use.

Examples include:

- Accessing a decoy administrative resource
- Using a fake credential
- Requesting a canary resource
- Accessing a hidden or decoy endpoint

When a trigger is detected, the application can generate a security
event.

## Deception Workflow

The general deception workflow is:

Suspicious Interaction
        ↓
Deception Resource
        ↓
Trigger Detected
        ↓
Security Event
        ↓
Wotmed-Net Telemetry

The exact event information will follow the telemetry format agreed
with the Wotmed-Net components.

## Wotmed-Net Integration

Deception events generated by the Demo Application will be provided
to the Wotmed-Net telemetry system.

This will allow the security event to be recorded and used by the
other Wotmed-Net components for detection and defense analysis.

## Implementation Approach

The deception mechanisms will be introduced gradually.

The initial implementation will focus on creating controlled decoy
resources and detecting interaction with those resources.

The behavior will be tested before connecting the deception events
to the complete Wotmed-Net telemetry workflow.
